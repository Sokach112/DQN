## Pong long run (`pong-tuned-s0`)

**Protocol.** PongNoFrameskip-v4, seed 0, Apple MPS, 1 training env, frame skip 4
(one decision = 4 emulator frames). Paper2013 CNN (16/32 conv, 256 hidden,
ReLU), MSE loss, Adam `1e-4`, batch 32, γ=0.99, vanilla target-network DQN
(no Double DQN), hard target copy every 1,000 gradient steps, one gradient step
per 4 decisions, replay 100,000 transitions (5.65 GB), warmup 20,000 decisions,
ε linearly 1.0 → 0.01 over 100,000 decisions. Greedy evaluation on 10 complete
games every 50,000 decisions (fixed reset seed +100); the incremental report is
preserved as [`verification/long_run_report.json`](verification/long_run_report.json).

The run was configured for 1,500,000 decisions (6M emulator frames) with early
stopping when two consecutive evaluations reach a 20.5 mean. A 6,300 s
wall-clock guard stopped it at 1,250,000 decisions (5M emulator frames); the +21
target was not reached.

non-zero (conv1 1.66, conv2 2.16), and the mean top-two Q gap is 0.040. The gap
was 0.030 at 600k decisions, so action preferences are still small — consistent
with the slow start and the large evaluation variance, not with a dead network.

## Multi-seed tuning at 1M frames

Two tuning directions from the 20k-transition pilots were repeated with three
training seeds at 200,000 decisions (800k emulator frames) each, on CPU:

| Variant | Learning rate | ε anneal (decisions) |
| --- | ---: | ---: |
| fast-eps | 1e-4 | 100,000 |
| slow-eps | 1e-4 | 250,000 |
| low-lr | 5e-5 | 100,000 |

Common protocol: replay 50,000 transitions, warmup 20,000, batch 32, target copy
every 1,000 updates, one update per 4 decisions, ε: 1.0 → 0.01, greedy
evaluation every 25,000 decisions (10 games, reset seed +100), final independent
evaluation on 20 games (two fresh reset seeds). Three runs per seed were run
concurrently; seeds were run in separate batches.

| Variant | 50k | 100k | 150k | 200k | Final 20-game mean_of_means |
| --- | --- | --- | --- | --- | --- |
| fast-eps | -21.00 ± 0.00 | -20.60 ± 0.36 | -20.70 ± 0.30 | -20.43 ± 0.74 | -20.55 ± 0.65 |
| slow-eps | -20.97 ± 0.06 | -21.00 ± 0.00 | -20.87 ± 0.23 | -20.43 ± 0.15 | -20.32 ± 0.18 |
| low-lr | -21.00 ± 0.00 | -20.87 ± 0.23 | -20.87 ± 0.23 | -20.53 ± 0.50 | -20.62 ± 0.40 |

Full per-seed detail, comparison tables and caveats: [`04_multiseed_2026-10-18.md`](04_multiseed_2026-10-18.md).

Interpretation: at 1M emulator frames none of the variants rises measurably
above random play, and the seed spread is at least as large as any
variant-to-variant difference. The 20k-transition pilot ranking ("faster
exploration is better") therefore does not reproduce at a longer matched
budget — the pilot differences were noise, not a reliable tuning signal.

## Softmax action selection

Implemented as an **optional** policy in `agent/atari_agent.py`
(`agent.configure_exploration(...)`, `action_selection` and
`softmax_temperature`), wired through `algorithm.action_selection` /
`algorithm.softmax_temperature` in `config/config.yaml` and `DQN.__init__`.
Behaviour:

- `epsilon_greedy` (default, unchanged): greedy argmax with uniform random
  replacement at rate ε, identical RNG order to the previous implementation.
- `softmax` (opt-in): samples `π(a|s) = exp(Q(s,a)/α) / Σ exp(Q(s,a′)/α)` with a
  numerically stable NumPy implementation; ε is not mixed in because Boltzmann
  sampling replaces the ε switch.
- `deterministic=True` is always the greedy argmax used for evaluation, in both
  modes.

Justification for keeping ε-greedy as the baseline: the assignment
(`tasks.pdf` §2) explicitly allows omission of softmax under the ε-greedy
allowance ("softmax increases exploration, but when using ε-greedy it is
generally not necessary to also use softmax"). Both the requirement's
deterministic argmax policy and a Boltzmann policy are available; the baseline
keeps the assignment's ε-greedy schedule and exposes softmax for controlled
comparison only. `tests/test_softmax.py` covers default behaviour, the
Boltzmann distribution, temperature effects, deterministic argmax and
configuration validation.

## Breakout and paper-scale completion: measured budget and exact approach

The 2013 paper trained each game for 10M emulator frames (= 2.5M decisions at
frame skip 4) and reports Breakout 168 (average) / 225 (best episode) and Pong
20 (average) / 21 (best). This machine measured:

- ~260–330 decisions/s on MPS when the GPU is exclusive; ~150–200 decisions/s
  on one CPU thread; concurrent jobs share the same hardware.
- Replay memory: 56.4 KB per stored transition (two 4×84×84 uint8 arrays).
  100k transitions = 5.65 GB; the paper's 1M-frame replay ≈ 250k transitions =
  14.1 GB; 1M transitions = 56.5 GB.

Therefore a paper-faithful 2.5M-decision run is roughly 2–3 hours per seed on
this laptop, and the paper's ten seeds per game are a multi-day serial workload
here. Exact commands:

```bash
# Paper-scale Pong (+21 target). Slower paper-style epsilon; larger replay.
python long_experiments.py --tag pong-paper-s0 --game PongNoFrameskip-v4 \
  --steps 2500000 --device mps --buffer-size 200000 \
  --learning-rate 1e-4 --learning-starts 20000 \
  --epsilon-timestep 250000 --start-epsilon 1.0 --end-epsilon 0.1 \
  --target-update-interval 1000 --test-interval 50000 --test-episodes 10 \
  --final-test-episodes 10

# Breakout, same budget.
python long_experiments.py --tag breakout-paper-s0 --game BreakoutNoFrameskip-v4 \
  --steps 2500000 --device mps --buffer-size 200000 \
  --learning-rate 1e-4 --learning-starts 20000 \
  --epsilon-timestep 250000 --start-epsilon 1.0 --end-epsilon 0.1 \
  --target-update-interval 1000 --test-interval 50000 --test-episodes 10 \
  --final-test-episodes 10
```

Notes and limits:

- `buffer_size` 200k needs ~11.3 GB of RAM. On a 24 GB machine do not run two
  such jobs concurrently; a CUDA host is preferable for the paper's full
  schedule.
- Checkpoints store only weights + metadata, not replay/optimizer/RNG state, so
  a run cannot resume exactly; keep it alive and use the periodic checkpoints
  for evaluation. `long_experiments.py` writes an incremental report so a crash
  does not lose measurements.
- The measured 100k-transition/1:4-update configuration reaches break-even Pong
  behaviour but not +21 within 1.25M decisions. The paper used a 1M-frame replay,
  a 1M-frame ε anneal (250k decisions) and one update per decision; the larger
  2.5M-decision runbook above closes the replay and exploration gap. Raising
  updates per decision toward 1:1 and running multiple seeds are the next
  experiments, and both are compute-bound on this laptop.
- Breakout was not run at paper scale in this session: even one seed is a
  multi-hour job, and a shorter run cannot be compared with the paper's 168.

## Limitations

- One machine, one MPS device; wall-clock numbers include concurrent CPU jobs
  where noted. Results are not a reproduction of the paper's GPU compute.
- The long Pong run uses seed 0 only and 10-game periodic evaluations; the
  fresh-seed verification is the less noisy number but still a finite sample.
- Multi-seed runs are 3 seeds × 200k decisions, not the paper's 10 seeds ×
  2.5M decisions; they bound pilot noise, not paper-level reliability.
- Breakout/paper-level performance is **not claimed**; only the measured
  throughput, memory budget and exact commands are provided.
